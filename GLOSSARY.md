# Local glossary

This repository owns its vocabulary. Only rows marked Accepted establish controlled terms. Pending definitions need local review against current contracts; previous review marks do not accept product behavior.

| Term | Definition | Avoid | State | Previous scope | Previous review |
| --- | --- | --- | --- | --- | --- |
| Acceptance | A decision to use a Revision for a stated purpose. | Passing checks; Validation | Pending local review | Shared | To be reviewed |

Its activation is Active; its availability can be Innate or Unlocked. | "Manual ability" or "activated ability" in new prose; a targeting control; every ability or every Innate Ability. | Agent | An AI agent working in the Mardwerk organization or on its projects, operated or directed by Kyle or Palme (`olofwk`). Claude and Codex are examples. | A human reviewer; a non-AI script | Pending local review | Shared | Reviewed (2026-09-28T21:47:16Z) |
| Automatic Ability | An ability that starts when its game-defined event or condition occurs, without the player invoking it. | Active Ability; a player-invoked ability | Pending local review | Tower Defense | Reviewed (2026-09-28T21:48:02Z) |
| BTD6 | Bloons TD 6, the reference game for the Default Profile and for Manga Mayhem's enemy baseline. | A Mardwerk product | Pending local review | Shared | To be reviewed |

| Upgrade code | Top-middle-bottom notation for Coat counts, such as `4-1-0` or `x-4-x`. Upgrade State code and Build code are allowed aliases. `4-1-0` gives exact counts; `0-0-0` is the base Tower. | Upgrade State | The counts of Coats across a Tower's three Styles, whether planned, generated or reached during play. Upgrade combination is an allowed alias. Use build only when the context clearly means Upgrade State; ask Kyle if unclear. | A software build | Pending local review | Tower Defense | Reviewed (2026-09-28T21:46:48Z) |
